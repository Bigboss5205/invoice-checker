# 发票批量查验（Windows 免安装版）

把发票丢进一个目录，双击程序，自动逐张到**国家税务总局全国增值税发票查验平台**
查验，并把查验结果存成 PDF，命名规则 `<原文件名>-已查验.pdf`。

验证码**默认弹窗人工输入**（这个平台的验证码自动识别成功率很低，
详见下文「验证码是怎么处理的」）；想试自动识别可以改配置开起来。

---

## 它做什么

```
发票目录/
├── 发票查验.exe          ← 双击这个
├── 2024-05-某某公司.pdf
├── 数电票001.xml
└── ...
```

双击后：

1. 扫出目录里所有发票（`.pdf` `.ofd` `.xml` 以及图片格式）
2. 从每张票里识别出查验需要的字段
3. 打开查验平台，逐张查验（**串行 + 限速**，默认每张间隔 8 秒）
4. 把结果页导出成 PDF，存为 `原文件名-已查验.pdf`
5. 结果同时记进 `发票查验记录.sqlite3`，方便追溯

已经有了 `-已查验.pdf` 的发票会自动跳过，重复运行不会白跑、
也不会浪费平台每天的查验次数。

## 快速开始

### 方式一：用打包好的 exe（推荐）

1. 运行 `build.ps1` 生成程序
2. 把 `dist\InvoiceCheck\` 里的**整个文件夹**拷到放发票的地方
3. 双击 `发票查验.exe`

> 第一次想先看看流程、不想真的去查平台：把 `config.example.yaml` 复制成
> `config.yaml`，把 `verify.driver` 改成 `fake`，结果是模拟的，但能走通全流程。

### 方式二：从源码运行

```powershell
pip install -r requirements.txt
python 发票查验.pyw
```

### 方式三：自己打包

在项目目录打开 PowerShell：

```powershell
.\build.ps1              # 目录版，启动快（推荐）
.\build.ps1 -OneFile     # 单文件 exe，拷贝方便但启动慢几秒
.\build.ps1 -NoOcr       # 不带验证码自动识别，体积小约 200MB
.\build.ps1 -SkipInstall # 依赖已装好，只重新打包
```

脚本会自动建虚拟环境、装依赖、调用 PyInstaller。
产物在 `dist\InvoiceCheck\发票查验.exe`。

**运行环境要求**：Windows 10/11 + 系统自带的 Microsoft Edge。
程序**不捆绑 Chromium**（省约 300MB），直接驱动系统 Edge。
没有 Edge 的话装个 Chrome 也行；两个都没有则需要额外 `playwright install chromium`。

## 验证码是怎么处理的

**默认：全部人工输入。** 每张票轮到时弹一个窗口显示验证码图片，你照着图输入，按回车或点「提交」。

### 为什么不默认自动识别

实测（2026-09）这个平台的验证码是这样的：

* **它要求「挑出指定颜色的字符」**——提示会写「请输入验证码图片中**蓝色**文字」，
  有时又变成「**红色**文字」，颜色会切换。一张图里混着好几种颜色的字符，只能填指定的那种。
* **字符是中文与字母混排的**（例如「村朋FQ」），比纯字母数字难认得多。

两件事叠在一起，自动识别的成功率很低。与其每张票都白等几轮重试（还容易认错、
认错了要重来），不如直接弹窗敲一下——**又快又不会错**。

### 想试试自动识别

把 `config.yaml` 里的 `captcha.auto_ocr` 改成 `true`：

```yaml
captcha:
  auto_ocr: true
  max_auto_attempts: 6
```

程序会先按提示做颜色分离（蓝/红各自分离）再交给 ddddocr，
认不出或认错就刷新一张重试；**实在不行仍然会弹窗转人工，不会卡住**。

### 人工弹窗的几个细节

* **弹窗顶部会写明该填哪种颜色**（例如「这张图里有多种颜色，只填【蓝色】的字符。」），
  并且**按原图提示的颜色分离出一张对照图**放在右侧——你照那张填就行。
  这一点很重要：图里混着好几种颜色的字符，只该填平台指定的那一种。
* 颜色分离按**饱和度**剔除底色。实测平台的验证码底是一大片灰粉色
  （RGB 183,117,131，占了整张图 59% 的像素），它红色通道也偏高，
  早先的规则会把这整片底当成红字、分离出一整块黑——看起来就像
  「只有蓝色能提取，红色就废了」。现在按饱和度把灰底挡在外面。
* **按回车，或点「提交」**——程序**不会**根据长度自动提交。
  图里字符总数可能多于要填的数量，到底几位取决于其中有几个是指定颜色的，
  **所以位数不固定，不能写死 4 位**
* 看不清就点「**跳过 / 换一张**」（或直接点图片）——会刷新一张新验证码再问你，不算失败
* 有倒计时（默认 180 秒），超时自动放弃该张，**不影响其他发票继续处理**

> 说明：颜色提示是程序**从页面上现读**的。万一读不到，弹窗会退化成
> 「只填平台指定颜色的字符」的通用提示；此时如果浏览器是无头模式
> （`verify.headless: true`，默认），你看不到平台页面，
> 就按图中**同一种颜色**的那组字符填，或点「跳过 / 换一张」换一张再试。

## 配置（可选）

**不放 `config.yaml` 也能跑**——默认就是查程序自己所在的目录。
要改行为，把 `config.example.yaml` 复制成 `config.yaml` 放在 exe 旁边。

最常改的几项：

```yaml
paths:
  workdir: "D:/发票"        # 发票不在程序目录时指过去

output:
  suffix: "-已查验"          # 结果命名后缀
  subfolder: ""             # 想单独放一个目录就写 "已查验"

verify:
  min_interval_seconds: 8   # 两张票之间的间隔。平台有风控，不建议小于 5
  headless: true            # false 会弹出真实浏览器窗口（想亲眼看平台页面时用）
  enabled: false            # 只识别字段、暂不联网查验

captcha:
  auto_ocr: false           # 默认就是全部人工输入；改成 true 才先试自动识别
  manual_timeout_seconds: 180
```

改完保存即可，**下次点开始查验时自动重读**，不用重装。

## 常见问题

**Q：为什么默认走旧版页面（`index.html`）而不是新版？**

因为新版有问题，而且是**平台自身的问题**，不是我们能绕开的逻辑错误：

新版查验页（`/fpcygzfw/`）是 Vue 单页应用。实测它依赖的
`assets_res/js/chunk-vendors.ccf6a1dc.js` **在服务器上并不存在**——
请求它时服务器返回的是 `index.html`（HTTP 状态还是 200）。
浏览器把 HTML 当 JavaScript 解析，直接报 `Unexpected token '<'`，
Vue 从未挂载、**整页空白**。日志里会明确写出这条：

```
脚本请求返回了 HTML（会让页面白屏）：…/chunk-vendors.ccf6a1dc.js [HTTP 200]
```

实测这个文件连打 45 次全部返回 HTML，所以不是网络抖动。

**旧版（`https://inv-veri.chinatax.gov.cn/index.html`）是普通 HTML 表单**，
元素就是最朴素的 id（`#fpdm` `#fphm` `#kprq` `#kjje` `#yzm`），
加载过程没有任何懒加载 chunk，稳定得多。所以程序默认用它。

想回到新版：把 `config.yaml` 里的 `platform.mode` 改成 `spa` 即可
（新版的选择器我保留在 `platform.selectors` 里，也已经实测校准过）。

**Q：某张票提示「页面已提交，但没能识别出结论」怎么办？**

> **这个坑已经修掉了。** 实测查明：旧版平台查验成功后，是用
> `window.open('jgbyz.html')` 把结果**开在一个新窗口**里的 ——
> 主页面既不跳转、`queryFpcyxx` 接口也不返回 JSON，结论只存在于那个新窗口。
> 早先的实现只盯主页面，于是**一次成功的查验被误判成「没能识别出结论」**。
> 程序现在会盯着平台弹出的窗口，从里面读结论，并且**从那个窗口导出 PDF**
> （那才是你要的「已查验」页面）。
>
> 另一个连带陷阱：结果页底部有一句固定说明
> 「说明：发票信息不符时不得作为财务报销凭证，任何单位和个人有权拒收并举报！」
> —— 里面带「不符」，而它**每张票都在**。如果直接拿整页文本匹配关键词，
> 会把每一张票都判成「不一致」。所以程序优先只读「结果：」那一栏的值，
> 并在兜底扫描整页文本前先把这句剔掉。

万一还是遇到，日志里有定位所需的一切：

```
本次验证码要求填【蓝色】文字
第 1 轮：填表+取验证码 7.8s，提交+等结论 30.0s，查验接口没返回
平台打开了新窗口（查验结果通常在这里）：about:blank
查验结论来自平台弹出的结果窗口：…/jgbyz.html
没能识别出结论：提交后主页面跳转 0 次；关键请求 1 个（GET …/jgbyz.html）
```

* **查验接口没返回 + 主页面跳转 1 次** → 点击触发了整页提交（表单被刷空了），
  站点的 ajax 处理没被触发。把这三行发出来即可定位。
* **查验接口没返回 + 关键请求 0 个** → 点击压根没生效（通常是浮层挡住了按钮）。
* **接口已返回但仍是「结果未知」** → 是结论关键词要补，
  把日志里的接口 JSON（存在查验记录的 `detail` 里）对照 `result_keywords` 加一条即可。

出错时还会在 `发票查验出错现场\` 存一份页面 HTML 快照，两者一起看最有效。

**Q：为什么每张票要等这么久？**

几个耗时点，以及程序怎么处理的：

* **取验证码图片**：旧版把验证码做成 `data:image/png;base64,...` 内联图，
  程序**直接解码这段 base64**，不再用浏览器截图——
  截图会等元素「稳定」而这张图的容器带动画，实测能白等 40 秒以上。
* **等结论**：接口一返回结论立刻结束（通常几秒）。只有接口没返回、
  要靠页面文本兜底时才会等满 `verify.result_timeout_ms`（默认 18 秒）。
* **两张票之间**：默认强制间隔 8 秒（`verify.min_interval_seconds`）。
  这是**故意的**，平台有风控，不要调小。

**Q：需要安装那个根证书（taxca.p7b）吗？**

**建议装。** 税局这个站点的 HTTPS 证书是税务自建 CA（税务电子证书一级根）签发的，
不在 Windows 信任库里。旧版页面顶部会提示：

> 您使用的是谷歌 xx 版本浏览器，请参照操作说明安装根证书再进行发票查验操作！

官方说明页写的是「如不安装本证书，则在使用 https://inv-veri.chinatax.gov.cn
访问本网站或提交发票查验请求时，会出现警告信息」。

程序这边设了 `ignore_https_errors`，所以**不装也能跑**（默认模式已实测跑通）；
但装上更稳妥，也避免浏览器层面的告警。证书可以从
`https://inv-veri.chinatax.gov.cn/ca/taxca.p7b` 下载，
双击后选「安装证书 → 本地计算机 → 受信任的根证书颁发机构」。

**Q：日志里出现「页面状态：{... inputs: 0, formItems: 0}」是什么意思？**

说明页面压根没渲染出来（就是上面那个新版 SPA 的问题）。
如果用的是 `mode: spa`，改回 `legacy` 基本就好了。

**Q：提示「找不到发票号码输入框（选择器可能已失效）」和上面那条有什么区别？**

- 「页面上找不到发票号码输入框。可能是①平台改版…」→ 页面根本没渲染出来
- 「找不到发票号码输入框（**选择器可能已失效**）」→ 页面渲染了，但元素定位不到，
  这才是**真的需要更新选择器**，跑 `scripts/discover.py` 即可

日志里还有一行「页面状态：{... inputs: N, formItems: N}」可以直接区分：
两个都是 0 就是没渲染；都是正常值就是选择器要更新。

**Q：确认是选择器失效了，怎么修？**

在项目目录运行：

```powershell
python -m scripts.discover
```

它会打开查验平台，把页面上所有输入框/按钮/图片列出来，
并且**直接生成一份可以粘回 `config.yaml` 的选择器建议**，
还会存一张整页截图（`discover.png`）供你对照。
把生成的 `selectors:` 段粘进配置即可。

（注意：如果页面压根没渲染出来——日志显示 `inputs: 0, formItems: 0`——
那么 `discover` 也抓不到东西，那是上面说的平台侧问题，不是选择器问题。）

**Q：提示「没有可用的浏览器」？**

装 Microsoft Edge 或 Google Chrome；或把 `verify.browser_channel` 改成 `auto` 让它自动找。

**Q：某张票一直提示「缺少字段」？**

这类票会自动弹窗让你补录。数电票（20 位号码）**不需要**发票代码和校验码，
但要填「开具金额（不含税）」——弹窗里会自动把用不上的框去掉，照着填就行。

**Q：扫描件 / 图片发票识别不出来？**

PDF 扫描件和图片需要 OCR。默认只装了 ddddocr，它对整张发票的识别能力有限。
要在构建时加入 PaddleOCR：

```powershell
.\.build-venv\Scripts\python.exe -m pip install paddlepaddle paddleocr
.\.build-venv\Scripts\python.exe -m PyInstaller ...   # 建议直接改 requirements 后重跑 build.ps1
```

代价是镜像/体积会大 600MB 左右。对大多数场景，
**直接在弹窗里手工补录几个字段**更划算。

## 自检

怀疑环境有问题时：

```powershell
.\.build-venv\Scripts\python.exe -m scripts.selftest
.\.build-venv\Scripts\python.exe -m scripts.selftest --browser   # 额外测浏览器
```

它会检查依赖、配置、字段解析规则、文件抽取、整条流程演练、
查验记录、界面可用性、验证码识别，并逐项给出结论。
**全程不联网、不查验真实发票。**

## 重要说明

**使用边界。** 全国增值税发票查验平台是税务总局提供的公共服务，
对每张发票有**每日查验次数限制**，也存在访问频率风控。本程序：

* 默认**串行**查验，每张之间固定间隔 8 秒，不会并发冲击平台；
* 靠文件名判断是否已查验过，**不重复查同一张票**；
* 只在本地保存结果，不上传任何数据到第三方。

请把它当作「替你把发票一张张手动查一遍」的效率工具，
而不是批量抓取工具。调低 `min_interval_seconds` 或并发运行多个实例
会触发平台风控，也可能违反平台使用条款——**请不要这么做**。

**关于验证码。** 平台的验证码是访问频率控制措施，本程序**默认全部人工输入**，
自动识别是需要你显式开启的可选项。请保持合理的使用节奏，
如果平台明确要求人工输入，请用弹窗人工完成。

**数据安全。** 查验记录、日志、结果 PDF 全部留在你的本机目录里。
程序不会向任何第三方发送发票信息。

## 已知限制

这些是**如实说明**：

1. **选择器已对着真实站点实测校准（2026-09）**，包括：入口地址、五个输入框、
   只读日期选择器、动态变化的第 4 个字段、查验按钮、验证码图片与刷新按钮。
   平台改版后仍可能失效，届时跑 `python -m scripts.discover` 重新抓一份即可。
   代码里没有硬编码选择器，改 `config.yaml` 就行。

2. **默认走旧版页面** `https://inv-veri.chinatax.gov.cn/index.html`（原因见上面那条 FAQ）。
   若改回新版（`platform.mode: spa`），**入口必须是根地址**
   `https://inv-veri.chinatax.gov.cn/fpcygzfw/`：直接访问 `/national-invoice-check`
   路由会让页面白屏（服务器对不存在的资源返回 index.html，浏览器当 JS 解析就报错）。

3. **第 4 个字段是动态的**：平台会随发票号码/代码把它变成
   「开具金额(不含税)」「校验码」或「价税合计」。程序会**读表单上的标签**
   再决定填哪个值，所以平台调整判定规则时不用改代码。
   个别版式若取不到对应的值，会弹窗让你补录。

4. **结论优先取自平台接口返回的 JSON**（`queryFpcyxx` 的 `CyjgDm`/`CyjgMsg`），
   页面文本兜底。若某天出现「结果未知」，把日志里保存的页面文本对照一下，
   补进 `result_keywords` 即可。

5. **验证码自动识别成功率有限**（原因见上一节），这是平台验证码的设计使然，
   不是程序缺陷。人工输入始终可用。

6. **图片类发票的 OCR 能力有限**。默认的 ddddocr 不是为整票识别训练的，
   识别不出时会转人工补录，属于预期行为。

7. **查验次数用尽**。平台对单张发票每天最多查验 5 次。用尽后该张会标记为
   「超次数限流」，换一天再跑即可（已有的结果不会重查）。

8. **真实发票的验证情况，如实说明**：

   * 在**新版页面**（`mode: spa`）上，一张 20 位数电票走完了完整流程并得到
     「一致」结论，字段识别全部正确、PDF 正常导出；
   * 在**默认的旧版页面**上，已实测确认平台会把结果开在**新窗口**
     （`jgbyz.html`）里，程序现在能读到该窗口的结论并从它导出 PDF；
     这条路径在自检里用**照真实结构搭建的模拟结果窗口**做了端到端回归
     （含「结果页固定说明带『不符』不得误判成不一致」这一条）。

   样本仍然只有一张，且平台侧偶发白屏，**建议首次使用时先拿少量发票试跑**，
   确认结果无误再批量处理。
